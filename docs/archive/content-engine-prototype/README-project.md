# Less

Read less. Know more.

Less 的本地内容引擎。已实现来源采集、原文版本、结构化提取、事件与证据、编辑审核、Brief / Today、Signal，以及机器辅助和抽样验收工作区。

产品与实施依据见 [doc](README.md)，选型和运行边界见 [技术架构](04-technical-architecture.md)，完整剩余范围见 [实施进度](../../../operations/implementation-status.md)。软件功能不等于完成真实内容验收；提取复核不等于事实核验或发布批准。

## 本地启动

前提：Python 3.12、uv、Node.js 22、npm、Docker Desktop、Codex CLI。Codex 已通过 ChatGPT 登录，且支持 `exec --ignore-user-config --output-schema`；本机验证版本为 0.154.0。应用在本机运行，Codex 推理仍需联网并占用账号额度。

```sh
make setup
make dev
```

- 工作台：<http://127.0.0.1:5173>
- API 文档：<http://127.0.0.1:8000/docs>
- PostgreSQL：`127.0.0.1:55432`；Redis：`127.0.0.1:56379`

`make dev` 启动 API、单进程 Worker、单个 Beat 和前端。启动前检查应用端口，避免旧服务未关闭时再启动 Worker。Ctrl+C 停止应用进程并给执行中的任务留出配置上限内的完成时间，数据库容器及卷保留。需要停止基础设施时使用 `docker compose stop`。不要同时启动两套本地服务。

默认不自动消耗 Codex 额度：采集自动运行，AI 提取由页面按钮或 CLI 入队。要启用采集后自动提取，复制 `.env.example` 为 `.env`，设置 `LESS_AUTO_NORMALIZE=true`，然后重启。AI 始终串行执行，首期每次调用超时 180 秒，临时失败最多尝试 3 次。登录失效或额度不足会暂停 AI 队列；处理原因后在页面点击“恢复处理”。

所有 AI 入口共用每日上限，默认按 `Asia/Shanghai` 自然日最多 10 次调用，重试也计入。达到上限的任务保留在队列，次日恢复；不是“每天必须调用 10 次”。`.env` 中可用 `LESS_AI_DAILY_LIMIT`、`LESS_TIMEZONE` 调整上限和时区，重启后生效。历史缺少尝试日志的记录保守计数并单独披露；调用次数不等于实际费用。

无需把 ChatGPT 登录信息复制进项目或容器，也不需要 API Key。`LESS_CODEX_MODEL` 为空时由 CLI 自身选择默认模型；项目会忽略用户 CLI 配置，隔离插件、工具和 hooks。需要指定模型时在 `.env` 设置账号实际可用的名称。

## 日常操作

1. 在来源管理检查来源状态，发起采集或等待下一次计划任务。
2. 在原始材料中打开一份材料，查看原始链接、保存快照、发布日期及段落。
3. 点击“开始 AI 提取”，等待 Worker 完成；对照原文引用检查摘要和陈述。
4. 填写复核人及说明，记录“提取符合原文”或“需要修正”。所有复核都是追加记录，重跑提取不覆盖它们。

页面入队操作依赖 Worker 和 Beat，通常下一分钟派发。单独运行前后端不会执行后台任务。需要立即串行处理时可以使用：

```sh
uv run less collect simon-willison
uv run less collect all
uv run less normalize <version-id>
uv run less normalize <version-id> --force
uv run less resume-ai
```

来源初始配置位于 `operations/source-registry.json`。`less seed` 仅插入不存在的来源，不覆盖数据库的健康信息和编辑操作。要显式应用该文件中的配置修订，运行 `uv run less seed --update`；变更写入审计日志。数据库是运行时真值，初始文件不是实时健康报表。

当前登记 13 个节点。首次实际检查有 11 个成功保存正文；OpenAI News 的正文访问 403、HN RSS 的 Feed 访问 502 已标为 Needs Review。详情见 [首次验证记录](../../../operations/reviews/2026-09-20-initial-validation.md)。

每来源默认每 6 小时采集，单轮最多处理 5 个条目。新 URL 优先，随后重查已知条目；每轮显示 Feed 总数及未处理数量。重试固定使用首次保存的条目批次。此采集方式不保证覆盖 Feed 已移除的历史条目，高频来源需调整频率/容量或人工补录。历史条目保持原始日期，不能计为当天新闻。

## Week 1 验收台

左侧“验收台”提供日报、抽样核查和人工工作计时：

1. 填写操作人。可使用已固定的首批 30 条样本（来自 74 个 Items、11 个来源），或创建新批次。样本在 AI 提取前按来源分散随机抽取，同一 Item 只取最新保存版本，保存随机种子和抽样总体。
2. 点击“准备本批提取”将尚未准备的样本入队，遵守每日调用上限。失败样本留在清单中，避免只审查成功结果；可以显式重新提取。
3. 打开样本，对照原始页面、保存快照和引用位置，逐字段选择正确、正确保留未知或有误。错误必须填写依据。未检查的字段保持“尚未核查”，不计入准确率；全部字段检查后才计为一个完整样本。
4. 展开“人工工作计时”，选择实际来源范围、工作方式、类别和筛选标准，再开始计时。结束时填写阅读量、候选数、入选数及可定位结果。同一操作人不能同时启动两次；跨午夜耗时按日分摊。两次基线是否可比仍需人工确认。
5. 选择日期导出日报。当天报告注明部分日窗口；手动采集与计划采集分开，漏调度也计入应执行次数。没有人工样本时准确率显示待核查，未实现的后续阶段指标保留未知。

字段核查绑定精确提取版本，旧表单在重新提取后会被拒绝；历史记录不可覆盖。多批次重复抽到同一 Item 不会增加累计样本数，累计质量使用该 Item 最新一条人工核查。字段核查不等于事实批准或发布批准。

```sh
uv run less report --date 2026-09-20 --output operations/daily/2026-09-20.md
```

日报是数据库的可读导出，不作为第二份可编辑真值。历史日期的来源状态、人工验收进度是导出时累计值；当日采集、处理和计时按所选日窗口统计。2026-09-21 已将首批抽样尚缺的 29 条提取入队，受每日 10 次上限约束；实际进度以工作台为准，人工复核与手工基线仍需真实操作。

## 编辑收件箱（Week 2 进行中）

左侧“编辑收件箱”支持手动建立事件骨架、关联某份保存版本的具体段落、添加关键陈述和 Supporting / Counter / Context 证据。一个原文可以关联多个事件，取消与恢复关联保留原有记录。

证据保存原文短摘录、来源根、针对的陈述、适用范围与利益关联；摘录必须存在于指定段落。新增证据默认未核验，需明确对照原文后记录核验人、时间和依据。

Value Gate 独立记录 Important 和 Useful 理由，至少一条成立才可通过。Quality Gate 检查每条关键陈述是否有已核验支持证据；背景不替代支持，反面材料必须明确处理，关键缺口未解决不能通过。两道门通过后才能入选；也可待核实、驳回、继续观察或仅存证。入选事件仍不是已批准的 Brief。

事件骨架、材料关联或证据核验变化时，两道门和编辑决定回到待判断。旧版本表单被拒绝，历史审核和取消的材料关联继续保留。陈述可修正正文、类型和关键性；修正时保留此前内容和证据核验记录，重新检查证据是否适用。

“事件聚类建议”提供第一版规则召回：比较主体、动作、对象、标题、版本、时间与共享原文，展示共同点和冲突。它不是语义模型，也不会自动合并；最多考虑最近更新的 200 个有效事件，展示前 50 对，明确披露范围。

在单个事件的“合并、拆分与恢复”中，可以选择最多 20 个事件合并，指定保留的主记录；或将选定原文和陈述拆成新事件。陈述/证据 ID 保持不变，旧事件保留映射，材料同时支撑其他陈述时保留原关联。合并后的旧事件和恢复拆分后产生的归档事件只读，可从列表勾选显示历史事件或沿操作记录查看。

每次聚类保存操作前的关联快照；恢复不删除事件，也不自动恢复此前批准的质量状态。若操作后的内容已经进一步修改，恢复会被拒绝，避免覆盖后来成果。所有受影响事件的两道门和编辑决定回到待判断，证据需要重新核验。并发操作使用按事件 ID 排序的行锁及修订检查。

机器辅助支持基于两份事件快照的语义配对建议、价值初筛与排序，以及事件和 Brief 草稿。引用依据限定于保存的原文段落，尚不自动遍历完整引用链。事件配对盲判与机器排除项抽查均保留固定样本和更正历史；日报记录机器候选与编辑活动，但这些活动数不能直接相减作为过滤率。

## 数据与备份

- 数据库保存来源、检查记录、材料版本、模型任务、人工复核及审计日志。
- `data/snapshots/` 保存按 SHA-256 寻址的不可变原文，文件先落盘，再写数据库引用。
- `data/`、`.env`、依赖目录不提交到 Git。`.env.example` 的数据库密码仅用于绑定回环地址的本地 Compose 环境。

```sh
uv run less backup
uv run less restore data/backups/<timestamp> --database-name less_restore_example
```

备份包含数据库 dump、原文快照及校验清单。恢复命令只允许新建 `less_restore_` 开头的数据库，并创建独立数据目录；不会覆盖当前数据库。它会验证恢复后全部原文引用。需要切换到恢复的数据时，按命令输出在 `.env` 设置 `LESS_DATABASE_URL` 和 `LESS_DATA_DIR` 后重启。备份/恢复工具当前仅支持默认的本地 Compose 部署。

## 验证与维护

```sh
make test
make api-types
cd frontend
npx playwright install chromium
npm run test:e2e
```

后端集成测试会创建并清理独立 `less_test_` 数据库，不修改业务数据。浏览器测试需要运行中的 API 和已采集材料；复核写入场景使用明确的测试夹具拦截，不向真实库写入假审批。前端类型来自提交的 `openapi.json`，修改 API 后执行 `make api-types`。

当前软件验证不代表已完成连续 3 天采集、两次人工筛选基线或 7 天内容验证；这些运行验收项继续按 MVP 文档记录。

### 聚类规则抽样复核

编辑收件箱的“聚类抽样与盲判”可固定一个开发或验收批次。按种子从最近 200 个活跃事件的全部配对抽取，包含未被规则召回的配对；保存当时的事件骨架、关联段落和机器结果。提交首次人工判断前不显示机器结果，原文不足时只能记为无法判断。更正采用追加记录并检查修订号，首次盲判与最新判断分开统计。错误率、明确判断覆盖率、未判断及同事件未获正向建议均独立列示。

此工具目前评估事件骨架规则，不等于完成独立的 30 组原始材料配对验收，也不自动通过内容审核。用途标签区分开发与验收，但不自动保证两批材料互不重叠，验收负责人仍需核对样本独立性。

### Brief 与有限 Today

“Brief 与 Today”支持从已入选事件起草，每条陈述选取已核验的证据，写明价值、变化与解释。提交审核后需显式核对原文再批准当前版本，随后可内部发布到当天 Today；每天最多 5 条。低产或无合格内容可单独保存当天编辑记录，不补造历史运行日。

内容修订保留旧版本并回到草稿，撤回与更正保留审核历史。事件、成员、陈述或证据变更会将关联 Brief 标为需重新审核；Today 不再展示失效正文。只有重新核验、保存新版本并批准发布后恢复展示。历史 Today 保留旧版本占位，不把已更正内容冒充当日原稿。机器起草也必须经过同一审核流程，次日阅读反馈单独保存。

### Signal 假设与反证工作区

Signal 保存可证伪判断、范围、观察期、否定条件、反证计划与负责人。新建为假设草稿；关联已核验原文证据、记录实际反证检索后，由人明确复评为 Candidate 或其他状态。每轮复评要求新的检索记录、来源独立性、替代解释和逐项反面证据处理。升级 Emerging 至少需两个不同事件和来源根；更高成熟度还须明确跨时间和持续验证依据，数量不代替人工判断。

Thesis 更正、证据重核与关联变化保留 Timeline；证据同时记录原始发生日期和本次加入日期。事件、证据或聚类变化标记 Signal 需复评，不自动改写成熟度或 Last Updated。没有找到反证须保留查询范围与缺口，不能据此宣称成立。工作区不会自动执行反证搜索或编造实际观察期。

### 次日阅读反馈与编辑日报

在 Brief 的版本面板中实际复读已发布版本后，可记录“仍愿意看”及原因。系统拒绝发布当日反馈，严格区分次日与更晚复读；重复提交保留历史，日报按读者与版本采用当日最新次日反馈。日报同时列出当日机器初筛、事件创建、最后审核动作、发布与 Signal 复评活动。活动数量不等于日末有效库存，也不能跨阶段相减当作过滤率。

### 机器辅助与漏选审计

“机器辅助”将事件起草、Important / Useful 初筛、事件语义配对和 Brief 起草保存为独立任务。四类任务与原文提取共用每日调用预算、串行执行锁和额度暂停状态。结果保存输入快照、提示版本、模型、尝试历史和引用；引用不匹配会失败。机器草稿不能核验证据、通过两道门或发布内容；应用草稿时检查事件和 Brief 修订，防止覆盖后续人工修改。

价值排序只使用与当前事件修订一致的成功结果，Important 或 Useful 达到阈值即可进入候选；不确定结果单列。可从候选或排除池固定抽样，先对照原文独立判断，再展示机器理由。首次盲判与后续更正分别计数，审计不自动改变 Value Gate。模型实际质量、独立材料配对验收和连续运行窗口仍需真实验证。
