# Brief 去重设计

状态：第一阶段已实现；运行记录与召回质量优化待后续验证。更新：2026-09-29。

相关：`01-less-lite-architecture.md`、`02-content-skill.md`

## 目标与判断单位

去重的目标是避免把**同一实质变化**反复写成新 Brief，同时保留真正的新进展。相同 ID 或来源链接只能提供精确线索；不同链接可能讲同一件事，同一篇原文也可能被后续 Brief 引用为背景。最终判断必须回答：相对已保留内容，新增了什么事实、能力、适用范围或判断价值？

重复报道或同一主张的跨渠道表达应合并；已有 Brief 的事实需要纠正时更新原 Brief；出现独立且实质的新进展时可以新建 Brief，并在正文中交代与旧内容的关系。不为去重新增 Event、Cluster 或长期候选库。

## 当前实现及增长问题

此前自动简报在每轮开始时通过 `all_briefs()` 读取完整 Brief（包括正文和来源），将全量 JSON 交给 Content Skill 做语义去重；保存前又读取全库。现在 `backend/less/digest.py` 先获取本轮候选，再通过 `backend/less/dedup.py` 从 SQLite 索引召回相关旧 Brief，单独进行比较。批次检查器由宿主以 `--host-checked` 运行；手工内容任务仍可用完整只读 Brief 列表检查。

这一改动针对的是每轮全量读取、临时文件和内容任务上下文随历史线性增长的问题。SQLite 的存储容量本身不是首先需要解决的问题。共享来源链接现作为比较线索，不能单独决定“同一变化还是后续进展”。

## 目标流程

1. **发现线索**：内容任务先发现、核验本轮可能值得保留的少量材料，提取标题、具体原文链接、发布日期和关键变化。
2. **精确匹配**：保存端查询已有 Brief ID 和经过保守规范化的具体原文 URL。URL 规范化应统一大小写规则、片段和明确等价的路径形式；不得随意删除可能影响页面身份的查询参数。精确命中应返回旧 Brief 供判断，不应仅凭共享链接自动丢弃新进展。
3. **候选召回**：根据标题和事实文本，在**全库索引**中检索相近 Brief，并补充近期 Brief。只把相关旧 Brief 的必要字段交给内容任务比较，不再交付完整历史正文。近期优先，但全库索引仍须能找出多月前的同一事件或产品。
4. **语义判断**：逐条区分重复、更新已有 Brief、独立新进展和不确定。比较具体事实与增量，不能只依赖标题相似度。歧义较大时不自动作为新 Brief 入库，留下需要复核的说明。
5. **保存前复查**：在同一保存事务内再次查询本批 ID 和规范化 URL，防止发现阶段之后出现精确冲突；批次内部也做检查。数据库约束仍是最后一道精确校验。若两次任务之间另有内容入库，其语义关系尚不能由这道精确检查完全覆盖，需在后续质量抽查中关注。

第一版候选召回继续使用 SQLite：规范化 URL 存入 `source_keys`，标题和事实正文使用 FTS5 trigram 检索，有剩余名额时补充少量近期 Brief。每条候选最多交给比较任务 12 条旧 Brief。索引随 Brief 新建、修改、删除同步维护，首次启用时回填旧记录。中文检索的召回质量仍需通过真实误判样本验证；近期记录不是唯一检索范围。

## 实施顺序

1. **已实现：替换全量传递和全量保存检查**。自动简报拆成“发现少量线索 → 宿主检索旧 Brief → 比较后筛选”，保存时使用定向查询，并同步更新 Content Skill 的输入约定和批次检查器。
2. **加入检索索引与运行记录**：记录每轮历史 Brief 总数、待比较线索数、每条召回的旧 Brief 数、去重判断及耗时。记录应轻量，且不保存不合格候选的完整业务档案。
3. **根据误判再升级**：抽查“重复内容再次入库”（漏判）与“新进展被误丢弃”（错判），同时观察耗时和内容任务上下文。只有关键词召回持续漏掉同义表达时，才考虑向量检索；不预先引入向量数据库。

手工 Content Skill 任务当前仍使用完整只读 Brief 列表进行批次检查。自动简报的第二次比较需要额外一次内容任务调用；只有存在待保留候选且需要历史或批内比较时才调用。被判为需要更新旧 Brief 或难以区分的条目进入 `needs_verification`，不会自动覆盖旧 Brief；这类去重待复核说明会出现在邮件中。

## 验收重点

- 同一 ID、等价原文 URL、本批内部重复能被发现；不同链接报道同一变化也能进入语义比较。
- 共享背景来源不会单独导致确有新进展的 Brief 被丢弃。
- 旧内容在较长时间后重现，仍能被全库索引召回；近期窗口只用于排序和补充。
- 每轮交给内容任务的旧 Brief 数有界；保存前不再加载全部历史正文。
- 更正已有 Brief、删除 Brief 后，索引与实际内容一致；检索失败时明确报告去重范围受限，而不是声称完成了全库语义去重。
